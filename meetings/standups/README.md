# Standups

Daily or async team syncs. **Most standups produce no note at all** — that's the rule, not a failure. Only write one when something durable emerged: a real blocker, a decision, a scope change.

- **Distill focus:** blockers (with owner), decisions, anything that changes a canonical file. One screen max — a standup note longer than ~150 words is over-documented.
- **Propagate:** a blocker that persists ≥2 standups belongs in the weekly brief's blockers section; a decision belongs in `decisions/`.
- **Don't:** mirror ticket status (that's Linear's job) or write a note out of ritual.

Parent contract (frontmatter, body structure, quality bar): [`../README.md`](../README.md)

> Default-taxonomy folder — delete it if the company runs no standups, rename it to match what the calendar actually calls this meeting.
