# Product

Sprint planning, design and engineering reviews, retros, roadmap discussions.

- **Distill focus:** scope decisions (in/out and *why*), trade-offs accepted, retro lessons, open technical questions with owners.
- **Propagate:** roadmap-level changes → `product.md`; real decisions (architecture, build-vs-buy, kill-a-feature) → `decisions/`; retro lessons that change how the team works → `ops.md` or `management/processes/`.
- **Don't:** mirror the sprint board or ticket-level detail — that lives in Linear; the note records *why*, the tracker records *what and when*.

Parent contract: [`../README.md`](../README.md)

> Default-taxonomy folder — split into `product/` + `engineering/` only when the volume genuinely demands it.
